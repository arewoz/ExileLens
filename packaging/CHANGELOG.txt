EXILELENS CHANGELOG
===================


0.5.0b1
-------

User-visible improvements (since 0.4.0b1)
-----------------------------------------

- **Diagnostics 2.0 (player-facing):** Application health and Report a problem
  flows with privacy-safe Copy diagnostics, support package export, and Advanced
  diagnostics (event history and technical report in separate collapsible
  sections).
- **Unified updates:** ExileLens always offers the newest verified official
  release (stable or beta) by version ordering. Update controls moved to
  Settings; dashboard footer and tray stay synchronized.
- **Structured error codes (M4.5):** Item Check, Path of Building, build,
  worker, and update failures show stable EL-* codes with recommended recovery
  actions. UNCERTAIN and UNSUPPORTED evaluation outcomes remain distinct from
  application errors.
- **Desktop polish:** Version footer, tray update actions, Discord and GitHub
  navigation icons, and Patreon support link in the dashboard.
- **PoB2 setup:** First-run and Settings can **auto-detect** a standard Path of
  Building Community (PoE2) installation when no folder is saved yet; Browse
  still overrides detection.
- **Item Check reliability:** If your selected build file changes or
  disappears on disk, ExileLens reloads safely and will **not** resume a check
  against rolled-back or missing build bytes while keeping the last working
  baseline loaded.

Internal reliability, diagnostics, and quality
----------------------------------------------

- Mandatory Windows PR validation for startup composition, unified updates,
  Diagnostics 2.0, and structured error regressions.
- Release build script stages ExileLensUpdater.exe into the distribution;
  packaged release gate blocks missing updater or build stamp.
- Secure update pipeline unchanged: Ed25519-signed manifests, SHA-256 verified
  downloads, external updater with rollback support.
- Release dependency lock refreshed (**cryptography 50.0.0**) with full
  `--require-hashes` closure for Windows builds.


0.4.0b1
-------

User-visible improvements (since 0.3.0b2)
-----------------------------------------

- **Paired offhand disclosure** is clearer when a two-handed weapon
  candidate would remove your equipped shield or change the active offhand:
  verdict and tooltip text name the real item PoB would drop, including swap-set
  quiver vs. primary shield cases.
- **Weapon and offhand** comparisons are more reliable for one-hand + offhand
  builds, bow + quiver builds, shield replacements, and two-handed weapon
  upgrades, with restoration of equipment and build context after each check.
- **Component-context Item Check** is more accurate for builds that use Path of
  Building weapon-set swap slots (refines evaluation and restore for the slots
  you are using; active weapon-set handling itself shipped in earlier betas).
- **Non-weapon Item Check** no longer crashes on some ring and accessory
  comparisons that previously failed during evaluation.
- **PoB import and load** is more stable: ExileLens avoids unnecessary reloads
  while your build file is unchanged, reducing flicker and failed comparisons
  after switching builds.
- **Worker stability** on Windows: improved Unicode handling for PoB subprocess
  output and safer recovery when the calculation worker stops unexpectedly,
  including deferred restoration so a late restore cannot show a false success.
- Overlay and hotkey behavior includes reliability fixes (missed key-up recovery,
  item capture routing, first-paint visibility for missing Item Check state).

Internal reliability, diagnostics, and quality
----------------------------------------------

- Component-level offense evaluation and contextual proof plumbing for
  weapon-set-aware measurements (not a separate player-facing mode).
- Expanded real-PoB regression corpus and community regression matrix coverage
  for weapon-set contexts, incompatible cross-base placements, and paired
  offhand scenarios.
- Mandatory P0 regression contracts and GitHub Actions PR validation on Windows
  (native Qt, release gate) for main-branch integration.
- Release workflow now runs source and packaged release gates plus mandatory P0
  regressions before publishing a GitHub Release.

Experimental / diagnostic-only (not normal product features)
----------------------------------------------------------

- Low-level contextual diagnostic and enumeration APIs used in tests and
  engineering diagnostics. These do **not** provide automatic whole-build
  cross-weapon-set evaluation in the desktop app.

Known limitations
-----------------

- Item Check still evaluates one hovered item at a time; it does not
  automatically compare every weapon-set combination across your whole build.
- Some mechanics remain intentionally cautious or unsupported (for example
  certain jewel sockets, multi-part skills without representative fixtures,
  and builds that require explicit uncertainty rather than a directional
  upgrade/downgrade).
- Path of Exile 2 **game client version** compatibility is not verified in
  this release manifest; only the supported Path of Building revision below
  is recorded.


0.3.0b2
-------

- Beta release with the latest main-branch fixes and improvements.


0.3.0b1
-------

- Item Check can now evaluate Jewels by comparing them against eligible sockets in
  the current build using real Path of Building calculations.
- New first-run setup flow for connecting Path of Building and selecting a build,
  with migration of existing settings from the legacy location.
- Optional "Ignore socketed Runes" Item Check setting, disabled by default.
- Discord/community and Report an Issue links added to the desktop UI.
- Improved Jewel evaluation performance.
- Item Check presentation is more compact and puts the most important result
  information first, with additional technical detail available through More
  Info / Advanced.
- Jewel placement results use player-facing descriptions instead of raw internal
  socket IDs.
- Dashboard, Settings and Setup now use a consistent dark visual language.
- Diagnostics now provides a clearer path for submitting reports through GitHub
  Issues.
- Tray menu simplified around quick actions with support links grouped under
  Help & Support.
- Improved PoB version/provenance detection and handling of stale or unrelated
  manifest information.
- Invalid Path of Building locations no longer overwrite the last working
  connection.
- Item Check now fails safely instead of producing an overly confident verdict in
  a rare offense-fallback case.
- Weapon-swap evaluation now uses the actually active weapon set.
- Improved fail-safe handling of malformed PoB calculation data.
- Improved passive-tree restoration after Jewel comparisons for affected build
  shapes.
- Fixed a shutdown crash and improved clean application exit.
- Dashboard/Settings now behave like normal desktop windows instead of remaining
  above unrelated applications.
- Known limitation: some special Jewel sockets that can alter passive-tree
  connectivity are intentionally excluded rather than risk returning an incorrect
  comparison.
- Known limitation: Jewel checks can take a few seconds on builds with many
  eligible sockets because each placement requires a Path of Building
  recalculation.

0.2.1b1
-------

- Improved supportability with safer early logging and crash diagnostics, plus
  privacy-safe diagnostic reports that can be copied manually when asking for help.
- Diagnostics now provide clearer recovery guidance, explicit access to local logs,
  and updated troubleshooting guidance for reproduction steps and screenshots.
- Packaged builds now identify their version and build more reliably, and can check
  the official GitHub Releases page for a newer version. You can check manually;
  ExileLens only notifies about updates and never installs them automatically.
- Improved compatibility with older PoB2 build/loadout APIs. ExileLens now falls
  back to the legacy synchronized tree, item, skill, and configuration set model
  when newer managed-loadout methods are unavailable, with an actionable error for
  unsupported partial representations instead of a raw Lua failure.


0.2.0b1
-------

- Item Check now evaluates items across multiple build areas instead of relying
  mainly on a single damage number: OFFENSE, DEFENSE, RECOVERY, and UTILITY.
- Items with meaningful trade-offs are now identified more accurately. An item
  that gains damage but loses important defenses can now show SIDEGRADE instead
  of a misleading UPGRADE.
- Build-breaking changes and other hard constraints are now considered before a
  directional verdict is shown.
- Resistance evaluation is more build-aware. Losing an important resistance cap
  or defensive threshold can prevent an item from being called an upgrade.
- Item comparisons now preserve the active Path of Building context more
  reliably, including equipment, active skill, skill configuration, stat set,
  loadout, passive tree, and other build state used for the comparison.
- Improved comparisons for weapon-dependent builds, including bows, quivers,
  crossbows, and other cases where changing equipment can change the skill or
  damage calculation used by Path of Building.
- ExileLens now tracks the exact build and item context associated with each
  evaluation. Results from an older build state or previous item are discarded
  instead of being shown for the wrong comparison.
- Clipboard duplicate detection is now separated from item comparison identity,
  reducing cases where a legitimate new comparison could be confused with an
  earlier clipboard event.
- Partial or unsupported Path of Building results now fail safely. When there is
  not enough reliable evidence for a verdict, ExileLens shows UNCERTAIN or
  Couldn't evaluate instead of guessing.
- Known zero values are now distinguished from missing or unsupported values,
  reducing false UNCERTAIN results when Path of Building legitimately reports
  zero.
- Improved detection of the damage components that actually matter to the active
  build, including builds where the relevant damage is split across multiple PoB
  outputs.
- Reduced unnecessary Path of Building recalculation during Item Check by
  batching more of the comparison work and reusing safe intermediate state.
- Improved restoration of Path of Building state after comparisons, reducing
  the chance that one Item Check affects the next one.
- Diagnostics now include the ExileLens version, build revision, runtime mode,
  and other safe build information to make bug reports easier to identify.
- Diagnostic and clipboard handling was hardened for privacy. Raw copied item
  text and other unnecessary clipboard contents are no longer included in
  persistent diagnostic output.
- Expanded real-Path-of-Building regression coverage for equipment changes,
  build context, damage composition, stale-result handling, and multi-axis item
  evaluation.


0.1.1b1
-------

- Item Check now measures the same main skill before and after an item swap,
  so comparisons are less likely to use the wrong skill.
- When damage cannot be measured reliably, the overlay now shows UNCERTAIN
  (Partial comparison) instead of calling the item a SIDEGRADE.
- Mods like "+1 to skill gem levels" now count as real offense.
- More items that Path of Building actually measured now get a real upgrade
  or downgrade instead of "unmeasured".
- DoT and similar builds (for example Essence Drain / Contagion) now pick the
  right PoB damage number more often.
- More Info now shows a DAMAGE REFERENCE section: which skill and which PoB
  damage number was used for the comparison.
- Item Check tooltip text stays readable on Windows Light mode (no black text
  on the dark overlay).
- The overlay has a close (×) button. Esc first closes More Info, then hides
  the overlay.
- Starting ExileLens no longer flashes a blank window on the desktop.
- The dashboard no longer pops up unexpectedly when the app starts from the
  tray.
- Items that would leave the build unable to meet attribute requirements are
  now marked NOT VIABLE instead of showing a misleading upgrade or downgrade.
- Losing elemental resistance cap no longer shows as UPGRADE; verdicts cap at
  SIDEGRADE, or DOWNGRADE when max hit drops.
- Resistance lines in Item Check now distinguish effective values from uncapped
  totals when the cap applies.
- Tiny sub-1% offense drift no longer triggers false upgrade verdicts.


0.1.0b3
-------

- Fixed Settings page readability: the scrollable Settings view now stays on the
  ExileLens dark theme instead of falling back to Windows Light (cream text on
  white panels).
- Fixed Item Check hotkey release tracking so Shift+C (and other bindings) are
  detected more reliably after the key is released.


0.1.0b2
-------

- Fixed item analysis after clicking "Copy Item" in the in-game trade/market UI.
  ExileLens now opens the comparison tooltip automatically when Path of Exile 2
  copies a listing to the clipboard, without pressing Shift+C.
- Fixed stale PoB build state: saved build changes are now actually reloaded
  instead of reusing old in-memory equipment.
- Added safer build revision tracking, last-known-good fallback, and build reload
  diagnostics.
- Fixed app lifecycle issues where ExileLens could keep running without a visible
  tray icon or accessible window.
- Relaunching ExileLens now brings the existing instance back instead of silently
  exiting.
- Improved Settings recovery for invalid PoB/build paths, including reset and
  clearer status/error messages.
- Added support for normal installed Path of Building Community (PoE2) layouts
  instead of requiring a developer/source checkout.
- Fixed invalid or incompatible PoB paths so ExileLens recovers into Settings
  with a clear error instead of crashing with a PyInstaller traceback.
- Reworked Item Check hotkey handling: Shift+C remains the default, is now
  foreground-aware, configurable, and no longer blocks capital C outside PoE2.
- Added Hotkey Change/Test UI, validation, conflict detection, and better
  diagnostics.
- Fixed cases where Item Check could stay on "Analyzing..." forever; requests now
  always reach a terminal state or clear error.
- Improved overlay reliability, error visibility, positioning, and multi-monitor
  recovery.
- Improved worker stability with timeouts, stderr draining, crash detection, and
  recovery.
- Added better tray controls: Open, Settings, Reload Build, Diagnostics, Logs,
  and Exit.
- Added broader regression coverage for all major equipment slots, build reloads,
  hotkeys, clipboard capture, lifecycle, and overlay behavior.
- Added a public-beta smoke test covering broken config, restart/recovery, build
  reload, hotkeys, market Copy Item, and clean shutdown.
