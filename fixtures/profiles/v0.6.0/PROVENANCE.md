# 0.6.0 profile fixture

A real ExileLens 0.6.0 profile, used by `tests/test_release_1_0b_upgrade_*.py`. It is **generated by 0.6.0's own code, not hand-written**.

- **Source:** git tag `v0.6.0` (commit `b9ab35a46cfbce2af529bc08c44f9d78d3865230`, "Release 0.6.0").
- **Old schema version:** `settings.json` `schema_version` = **23** (the current code writes 25).
- **Files:**
  - `settings.json` — written by 0.6.0 `AppSettings.save_settings`, so it has exactly the keys 0.6.0 persists (including `dedup_window_seconds`, `live_market_mode: "auto"` and `update_channel: "beta"`, and none of the later privacy / market-consent / What's New keys).
  - `item_history.json` — written by 0.6.0 `PersistentItemHistory.record`. 0.6.0 persists only summary fields per entry (id, status, baseline identity, evaluation context/identity, content hash, item name, verdict, best slot, seen count, stale); it does **not** store the full result payload, so a 0.6.0 history file holds no price, power-per-currency or value-class fields.
  - `generate_fixture.py` — the exact generator.
- **Procedure:** `git worktree add --detach <tmp> v0.6.0`; with `PYTHONPATH=<tmp>/src` and `LOCALAPPDATA` pointing at a fresh temp directory, run `generate_fixture.py <out>`. It constructs `AppSettings()`, sets the user-level fields a real profile holds (PoB / build path, hotkey, loadout and item set, overlay and dashboard geometry, pinned overlay slots, league choice, update state, UI scale, hint counters), calls 0.6.0 `save_settings`, then records one evaluation with 0.6.0 `PersistentItemHistory`. The script asserts it is running 0.6.0 code (schema 23). The temp worktree was deleted afterwards.
- **Scrubbed:** no real path, username, machine id, token or Patreon credential exists in the profile. The PoB and build paths use the placeholder user `C:\Users\Player\...`, keeping the real directory structure. The history entry uses a synthetic item (`Example Rare Helmet`) and an all-zero-style content hash.
- **Not captured:** files only the packaged app writes (build cache, cloud/Patreon state, `trade2_policy.json`, logs). The real binary 0.6.0 → 1.0.0 in-app update is a separate 1.0-E check; see `docs/1.0-HARDENING-PLAN.md`.
