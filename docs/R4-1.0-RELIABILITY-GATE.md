## 4. `stat_stacker`

**Meaningfully distinct from `attribute_stacker`, and representable without a new fixture.** The category has no definition in the repo; it is read as a
stat that is neither an attribute (Str/Dex/Int) nor a resource pool (Life/ES/Mana, covered by their own categories) and that PoB converts into damage or
defence. The existing Giant's Blood build (`corpus02_giants_blood_shield.xml`) already contains the mechanic: Chernobog's Pillar, "Gain 1% of damage as Fire
damage per 1% Chance to Block". R4 adds one real-engine case on it (`test_block_chance_stacking_is_measured_through_the_damage_conversion`): less Block lowers
**both** damage and EHP, Item Check reports a FULL downgrade on both axes equal to an independent cold PoB load; more Block is already capped, PoB says so and Item
Check reports a SIDEGRADE rather than an invented gain. No synthetic category fill: the fixture is a real public build, the candidate is the equipped shield plus one line.

Scope, stated plainly: **one stacker flavour on one build.** Armour/Evasion/Rage/charge stackers have no corpus build. ExileLens adds no stat-specific formula (PoB computes
them) and the generic measurement path is the same one the attribute and ES cases exercise, so this is a documented limitation (§9), not a release gap.

## 11. The 1.0 reliability gate

Run: `python scripts/generate_corpus_coverage_report.py --check-gate` (coverage half, exits non-zero when blocked; leave `POB2_PATH` unset so the installed PoB is used)
and `python scripts/r4_gate_measure.py` (Build Intelligence half, exits 1 when blocked). Rules live in `tests/corpus_coverage/gate.py`, unit-tested without PoB.

**BLOCKS 1.0 if** (each is a named check):

- any case graded WRONG_RESULT / WRONG_UNCERTAIN (`NO_WRONG_RESULT`);
- any restore / state-integrity case fails (`RESTORE_AND_STATE_INTEGRITY`: loadout, weapon set, jewel socket, transaction, restore recovery);
- a registered case did not execute, or **any failing test in the executed suites is not a registered case** (privacy scan, manifest, corpus loads);
- a verdict-level case is neither classified nor declared state-integrity; a refusal or partial case has no audit; a case is flagged `blocks_1_0`;
- an archetype has no case, or has no FULLY_MEASURED verdict case and is not listed with a documented reason;
- the executed-case or FULLY_MEASURED ratchet drops (below);
- Build Intelligence: any build fails to analyse, restore changes the fingerprint, a lane is unordered or unlabelled, rescore is impure or makes a PoB call, staleness is wrong, a per-point/normalised field exists, a no-evidence build is silent, or the cache serves a stale or fails to reproduce an analysis.

**ALLOWS 1.0 with documented limitations**: an intentional, explained UNCERTAIN; rare unsupported mechanics that refuse truthfully; PoB itself unable to establish the result; a niche
mechanic with an explicit safe fallback. Audited FIXABLE gaps are listed as INFO, not blockers.

**Thresholds come from evidence, not round numbers:** `MIN_EXECUTED_CASES = 188` and `MIN_FULLY_MEASURED_CASES = 91` are the counts measured in this pass and only ratchet up when the corpus grows.
`unusual_skill_part` is the single archetype allowed below FUNCTIONALLY MEASURED, with its reason in the gate.

Result today: coverage gate **PASS**, Build Intelligence gate **PASS**.

## 12. Conditions and remaining limitations

No release **blocker** under the gate. Conditions for calling 1.0 reliable:

- **C1 (owner):** the 40 `Unique ID:` lines and two character hashes remain in the Git history of #58. Removing them from history is an owner decision.
- **C2 (process):** CI runs none of the Item Check tests, the coverage report tests, or the gate; it needs a local PoB, so it is a release-time step. Run both halves on the release candidate and
  against whichever PoB ships. Adding the engine-free tests (about 20 s) to PR validation is recommended, not done here.
- **C3 (PoB):** the gate was measured on one runtime. Results are PoB-revision-specific (§1). Re-run it whenever the supported/recommended PoB changes.
- **C4 (accept):** the documented limitations: ignite/bleed-dominant and totem-count PARTIAL, one build per thin archetype, no bleed-dominant build, no Armour/Evasion/Rage/charge stacker, no
  sinister-socket fixture, same-name jewel sockets indistinguishable in the tooltip, and the legacy `recommendation.verdict` payload field that still says STRONG_DOWNGRADE for the Chernobog case
  while every user surface and `authoritative_public_verdict` say UNCERTAIN (CORPUS-02A FU-1; latent, no consumer reads it for display).
