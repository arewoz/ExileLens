# ExileLens 1.0.0 hardening plan

Source of truth for the final release work. Written on `origin/main` `546ed98` (R5-C merged), code version `0.7.0b1`, public stable predecessor `v0.6.0` (tag `b9ab35a`, 13 commits / 322 files behind HEAD).
This is an audit and plan. Nothing here has been implemented, published, tagged or version-bumped.

Evidence labels: **[verified]** = I read it or ran it in this pass; **[audit]** = reported by a read-only code audit of that area and spot-checked where it decides a classification; **[needs-external]** = depends on GitHub/Windows state that cannot be seen from the repository.
Classification: **P0** must fix before the 1.0 RC · **P1** should fix before public 1.0 · **P2** safe after 1.0 · **BLOCKED_EXTERNAL** · **NO_ACTION** (audited, acceptable).

## 1. Executive release status

- **No engine, privacy-model or updater-architecture defect was found.** Item Check / Build Intelligence passed the R4 gate (conditional, see §13). Network defaults, update authority, rollback and fail-closed behaviour hold on every path read.
- **What is not ready is the public surface and the evidence.** The shipped `packaging/README.txt` makes false statements (no telemetry system; optional live market pricing; "early beta"; the removed "Value for My Build"), the release notes / changelog / What's New describe `0.7.0b1`, the release workflow hard-codes "- Beta" in the GitHub release title, third-party notices and LICENSE are not shipped in the ZIP, and there is **no real 0.6.0 profile, no 0.6.0 → 1.0.0 in-app update evidence, and no packaged-build network/clean-install evidence.**
- **Not blockers (accepted):** the live trade provider is POLICY-BLOCKED, R3 real account sync is absent, no paid Windows code signing (stated policy; manifest signing is separate), R6 is post-1.0.
- **Shape of the work:** five slices (§20), three of which can run in parallel, converging on one RC gate. Nothing requires an engine change.

## 2. Fixed product / release decisions

1. 0.7.x builds are internal. **Do not publish 0.7.0 / 0.7.0b1.** The next public release is **1.0.0**; the public predecessor is **0.6.0**.
2. The What's New entry and release notes describe **0.6.0 → 1.0.0**, not internal 0.7 builds.
3. The code version stays `0.7.0b1` until RC/final release prep. The bump is one central change (§19).
4. No public release, tag, GitHub Release or manifest without **explicit owner approval**.
5. Live trade provider POLICY-BLOCKED: accepted, not a 1.0 blocker; the market is not advertised. R5 is closed for 1.0 (R5-D deferred).
6. No paid Windows Authenticode signing for 1.0. Update-manifest (Ed25519) signing stays separate and is unchanged; **no key rotation** in this work.
7. PoB remains the only supported build source; R3 runs independently and is not a 1.0 dependency.

## 3. Current blockers

None are engine blockers. The P0s in §4 are copy, compliance and evidence items; the longest-lead item is the real-binary 0.6.0 → 1.0.0 update test (it needs a candidate artifact, so it sits in the RC slice).

## 22. Release-candidate definition

A build is a **1.0 RC** only when all hold on one commit: all P0 closed and P1 closed or explicitly accepted by the owner; release copy final; version bumped centrally and `release-gate` + `release-regressions` pass; **R4 gate fresh** on that commit (§13); `release.yml` `dry_run=true` green and the artifact SHA recorded; provenance + leak scan clean, no secrets/paths; clean install passes (§7); **0.6.0 → RC in-app update passes** with settings/pins/build preserved and rollback proven; updater tests incl. cancel/no-op pass; packaged network smoke shows only the allowed GitHub hosts (and nothing under `no_network`); packaged UI smoke (§15) passes; Defender/VirusTotal results recorded for both exes; PR validation + smoke green; GitHub environment/branch settings evidenced (§19). **An RC is not a public release.** The owner must explicitly approve before any tag, GitHub Release, manifest or announcement.
